# EasyQ Support

**EasyQ Support** is the remote help client of [EasyQ](https://www.easyq.gr), print shop management software. It is
[RustDesk](https://github.com/rustdesk/rustdesk) with a small set of changes, built from this repository, in two
variants:

| Variant | Who runs it | What it can do |
|---|---|---|
| **EasyQ Support** (`customer`) | An EasyQ customer, started from EasyQ when they ask for help | Incoming only: a small window with its ID; every connection needs the user's "Accept" |
| **EasyQ Support Tech** (`tech`) | EasyQ's own support staff | Outgoing only: connects to a customer's EasyQ Support; never accepts a connection |

Nothing is installed and nothing runs after the window is closed.

## What is different from RustDesk

All changes are in [`easyq/apply.ps1`](easyq/apply.ps1) (`-Variant customer` or `-Variant tech`), applied during the
build: settings in `libs/hbb_common/src/config.rs`, and EasyQ's icons from [`easyq/branding/`](easyq/branding)
instead of RustDesk's (`res/icon.ico`, `res/tray-icon.ico`, `flutter/windows/runner/resources/app_icon.ico`,
`flutter/assets/icon.svg`, and `flutter/assets/logo.png` when there is one).

| Change | Why |
|---|---|
| App name `EasyQ Support` / `EasyQ Support Tech` | Its own settings folder: a RustDesk the user already has keeps its settings and does not affect this client |
| `conn-type = incoming` / `outgoing` | The customer's client cannot be used to reach other computers; the staff client cannot be reached |
| ID / relay server `remote.easyq.gr` and its public key, also as the built-in production server | EasyQ's own server instead of RustDesk's public servers; the client knows it is not on a public server (no "set up your own server" hint, no public-server quality cap) |
| `approve-mode = click` | Every connection needs the user's "Accept"; there is no password to ask for |
| No installation, no settings page, no account, no address book | Only a one-time, user-started session |
| No API server (`register-device = N`) | The client never calls RustDesk's admin server |
| No update check, no LAN discovery | Nothing besides the session itself |
| EasyQ icons and logo | The customer sees at once that it comes from EasyQ |

Everything else is RustDesk, unchanged.

## How it is built

- Branch `easyq-1.5.3` = RustDesk tag `1.5.3` + `easyq/` + `.github/workflows/easyq-build.yml` + this file. One branch
  per RustDesk version, named `easyq-<version>`; the default branch is the one EasyQ ships today.
- `.github/workflows/easyq-build.yml` (run by hand) builds Windows x64 with RustDesk's own build steps and the
  changes above, once per variant, and uploads the unsigned files as two artifacts. It is generated by
  [`easyq/make-workflow.js`](easyq/make-workflow.js) from RustDesk's `flutter-build.yml` of the same version, never
  edited by hand.
- The files are then signed by EasyQ with its own code signing certificate and published.
- A new RustDesk version: a new `easyq-<version>` branch from the new tag, the same `easyq/` folder, then
  `node easyq/make-workflow.js`.
